Sprite Display is a data pack for quickly and easily summoning Text Displays that contain a single atlased sprite. It includes functions for summoning and scaling sprites, as well as an entire internal database of available atlased sprites, viewable with the `/function sprite_display:browse` function. Since this browsing function displays the sprites in chat, they are not correctly scaled, and are squished into a square. Clicking on a sprite in the browser will suggest a command to summon that specific sprite.

Every summoned Sprite Display is tagged with `sprite_display` so you can more easily teleport, rotate, and rescale them. For example, `/kill @n[tag=sprite_display]` will delete the nearest Sprite Display, and `/execute as @n[tag=sprite_display] at @s run rotate @s ~15 ~` will rotate the nearest Sprite Display by 15 degrees.

Here are all of the important functions of the pack:

| Command | Description |
| --- | --- |
| `/function sprite_display:summon {atlas:<atlas>,sprite:<sprite>,width:<width>,height:<height>,scale:<scale>}` | Summon a Sprite Display. While you can enter this information manually, it is also possible to grab it from the internal `sprite_display:sprite_data` storage like this:<br>`/function sprite_display:summon with storage sprite_display:sprite_data particles."vibration"` |
| `/function sprite_display:set_scale {scale:<float>}` | Set the nearest Sprite Display's scale to a specific number. Scale is always in the unit of block-pixels, so a scale of 1.0 means each pixel in the Sprite Display is exactly the same size as a pixel on a block. |
| `/function sprite_display:rescale {scale:<float>}` | Multiply the nearest Sprite Display's scale by a specified amount. Unlike the `set_scale` command, this function is additive, so running the function multiple times with a scale of 2.0 will make the Sprite Display continue to grow. |
| `/function sprite_display:browse` | Shows all available atlased sprites in the chat. Each sprite suggests a command for summoning a Sprite Display when clicked. This function is generated by the `generate_sprite_library` Python script. |
| `/function sprite_display:vanilla_friendly_browse` | Shows all available atlased sprites in the chat. Unlike the normal `browse` function, it suggests a regulary summon command that can be used to create the Sprite Display even when the data pack is not installed. As such, you could delete every other file in the data pack except for this one and still get most of the value of this pack. The `set_scale` function will not work with displays summoned like this, but the `rescale` function will. This function is generated by the `generate_sprite_library` Python script. |
| `/function sprite_display:debug_entity` | Summons a Text Display with every single sprite in it. This is just for debug purposes, but it's a fun way to look at everything. This function is generated by the `generate_sprite_library` Python script. |
| `/function sprite_display:load` | This is an internal command that runs when the server starts. You do not need to worry about it or ever manually run it. Good job on reading the documentation thoroughly though, that's a pretty epic win. This function is generated by the `generate_sprite_library` Python script. |

## Technical Details
Since a sprite text object is always squashed into a square when rendered, and sprites come in a bunch of different shapes and resolutions, very specific calculations must be performed on the Text Display's scale and translation in order to summon a centered sprite at block-pixel scale.

First, you take the width and height of the sprite you are trying to render in pixels, and multiply both values by `0.3125`. These are used as the X and Y scale in the Sprite Display.

You then take the resulting scale values, multiply the X by `-0.025` and the Y by `-0.15`. This is what ensures the sprite is properly centered.

As an example, a 16x16 sprite like a block or item texture will require a scale of `[5,5,1]` and a translation of `[-0.125,-0.75,0]`. For a 64x48 sprite, a scale of `[20,15,1]` and a translation of `[-1.6,-7.2,0]`.

The `vanilla_friendly_browse` has these scalings premultiplied directly into the command, so no math is required. However for the main `browse` function, I opted instead to only store the original pixel measurements, and have the summon and scale functions perform the necessary math on the fly. This is so I can quickly and easily add a new texture to an atlased folder in a resource pack, type in its width and height, and then instantly have it as an entity in-game.
